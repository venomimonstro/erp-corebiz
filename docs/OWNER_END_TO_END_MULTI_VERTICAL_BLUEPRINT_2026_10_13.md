# CoreBiz — целостная ERP для 17 видов бизнеса: поэкранный путь владельца

Дата: 13.10.2026. Статус: продуктовая спецификация, ревью структуры исходников, не подтверждённый production GO.

## Главные правила

1. Клиент покупает одну SaaS-подписку, создаёт компанию, выбирает нишу и получает готовые процессы. Выбранная ниша меняет интерфейс и требования, но не заводит вторую CRM, второй каталог, второй финансовый или складской учёт.
2. Tenant изолирован от другого tenant. Внутри компании может быть несколько юрлиц, филиалов, мест продаж, складов и направлений. При смене ниши данные не удаляются.
3. Услуга/товар, клиент, ресурс, складской остаток и финансовое обязательство имеют единственный источник правды. Витрина, касса, заказ и аналитика читают одни бизнес-сущности.
4. Выполнено ≠ оплачено ≠ фискализировано ≠ отгружено. Эти этапы подтверждаются независимо через доменные события и проверенные внешние результаты.
5. История не перезаписывается сменой цены; покупательские платежи, возвраты, резервы, зарплата, начисления и расходные материалы идемпотентны.
6. Зелёный индикатор «первую операцию сделали» не заменяет полный GO/NO-GO, включая реквизиты, кассу, платежи, права, интеграции и тест восстановления.

## Единый порядок для владельца

**0. Зарегистрироваться.** Email, пароль, название компании, предварительный вид бизнеса. При сетевой ошибке проверить, создался ли аккаунт; не создавать новую компанию вслепую.
**1. Купить доступ.** Открыть тарифы, увидеть лимиты и сумму, подтвердить платёж. ACTIVE только после сверки у PSP. При задержке webhook показать PENDING/UNKNOWN с безопасной сверкой, без двойного списания.
**2. Выбрать профиль.** Салон, магазин, склад, авто, студия, агентство и прочие. Включить профиль и специализированную навигацию; при смене профиля исходные данные сохраняются.
**3. Указать компанию.** Реквизиты, систему налогообложения, часовой пояс, филиалы, счета/кассы. Неполные данные допустимы как черновик, но не как подтверждённая фискальная готовность.
**4. Пригласить команду.** Владелец, администратор, кассир, специалист и бухгалтер имеют разные права; рабочий ресурс без логина не равен учётной записи.
**5. Загрузить базу.** Ручной ввод либо CSV/Excel с предпросмотром ошибок, дедупликацией, импортом и сверкой.
**6. Настроить операционные справочники.** SKU, услуги, цены, себестоимость, договоры, склады, ресурсы, расписания, каналы.
**7. Подключить внешние системы.** Платежи, ККТ/OФД, доставка, маркетплейсы, банки. Показывать реальные статусы и пределы интеграции.
**8. Выполнить первую пробную операцию.** Сохранение → повторное чтение → изменённое состояние → склад/оплата/зарплата → проверка отсутствия дублей.
**9. Пройти Go-Live.** Отдельно проверить целевые бизнес-процессы, восстановление после ошибок, реальные права и стабильность.
**10. Управлять ежедневно.** Заказы, визиты, долги, остатки, прибыль, начисления, сверка, ошибки интеграций.

## Универсальные экраны: действия и негативные сценарии

| Экран | Что заполнить | Критерий успеха | Ошибка → безопасное восстановление |
|---|---|---|---|
| [Тариф и оплата](/app/settings/billing) | тариф, лимиты, способ оплаты | Подписка ACTIVE только после подтверждения провайдера | Платёж UNKNOWN / отменён → Сверить платёж; не активировать доступ и не списывать деньги дважды |
| [Выбор бизнеса](/app/start) | ниша, компания, смешанные процессы | Профиль применён, права и меню обновились | Сбой сети / выбрана не та ниша → Прочитать профиль повторно; менять без удаления старых данных |
| [Реквизиты компании](/app/settings) | ИНН, тип юрлица, налоговый режим, валюта, часовой пояс | Для фискальных операций реквизиты проверены | Неверный ИНН / неизвестная система налогообложения → Сохранить черновик и блокировать только юридически значимую операцию |
| [Команда и филиалы](/app/settings/team) | филиал, роль, приглашение, границы финансов, учётная запись | Сотрудник видит только свой tenant и разрешённые функции | Приглашение истекло / лишние права → Повторить приглашение без повышения роли; проверить RBAC |
| [Импорт старых данных](/app/migration) | источник, сопоставление, предпросмотр, дубли, сверка | Повторный импорт не дублирует данные | CSV испорчен / не совпадают суммы → Остановить импорт, дать исправить карту полей, повторить идемпотентно |
| [Интеграции](/app/settings/integrations) | провайдер, полномочия API, тест, касса, платёж, доставка | Подключение подтверждено с нужными правами | API 401 / webhook потерян / ККТ недоступна → Оставить UNKNOWN, сверить провайдера, не создавать дубль |
| [Проверка запуска](/app/settings/go-live) | готовность ниши, права, первая тестовая операция, интеграции | GO разрешён только после доказательств по обязательным узлам | Не пройден платеж или нет запасов / слотов → NO-GO и список причин, без фиктивной готовности |
| [Ежедневное управление](/app/operations) | заказы, визиты, долги, остатки, прибыль, расхождения | Владелец видит источник каждого показателя и проблемной операции | Данные задержаны / платёж UNKNOWN → Показать возраст данных и ссылку на исходную операцию |

## Матрица целостности и сценариев сбоев

| Сбой | Ожидаемое поведение |
|---|---|
| Регистрация 2 раза | Один tenant / отказ дублю email; контроль выдачи первой сессии |
| Два клиента за последний слот | Один успешный визит, второй получает конфликт и альтернативы |
| Два заказа за последний SKU | Неотрицательный ATP, один подтверждённый резерв |
| Запись завершена дважды | Ровно один набор материальных списаний и начислений |
| Два webhook одного платежа | Одна финансовая проводка, нет двойного списания |
| Провайдер оплаты/ККТ недоступен | UNKNOWN/PENDING, серверная сверка, нельзя имитировать чек |
| Запрос накладной не ответил | Сверка по исходному заказу, а не вторая отгрузка |
| Возврат частично проведён | Суммы и первоначальная продажа связаны; нет двойного возврата |
| Сотрудник без finance.read | Не видит расчёты владельца и коллег, но работает со своим расписанием |
| Владелец переключил компанию | Права и данные пересчитаны из tenant-контекста |
| Подписка истекла | GRACE/READ_ONLY без удаления, возможность восстановления и экспорта по политике |
| Импорт CSV с плохими данными | Dry-run с ошибочными строками, отсутствие частично скрытого импорта |
| Загрузка 390px / нет связи | Рабочий мобильный экран, явные ошибки и повтор без ложного успеха |
| Нужного провайдера нет | Показать отсутствие готовности и допустимый ручной путь, не заявлять поддержку |

## Бизнес-модель и ежедневное закрытие

**Каждый день:** владелец открывает задачи, заказы, записи, заполненность ресурсов, платежи/долги и незакрытые ошибки; каждая цифра ведёт к исходной операции. **Каждую неделю:** загрузка, оборачиваемость, возвратность, закупки, себестоимость и дебиторка. **Каждый месяц:** зарплатные начисления, кассы/банки, налоги, прибыль по филиалам и настройки тарифных лимитов.

## Самотест и фактический статус

Каталог включает 17 отраслей × 5 специальных экранов = 85 экранов, плюс 8 общих экранов. Всего в расчёте по всем профилям 221 контрольный шаг; у каждого есть положительный результат, типовой отказ и восстановление. Дополнительно подготовлен тест `scripts/owner-industry-journeys.test.mjs`: он проверяет покрытие всех отраслей, наличие ссылок в меню и наличие полей/условий/восстановления, а также репетирует отказ на каждом шаге.

**Ограничение:** структурная модель и офлайн-репетиции не доказывают работу HTTP, PostgreSQL, платежей, налоговой интеграции или реальной команды. Для коммерческой приёмки обязательны `pnpm typecheck && pnpm test && pnpm build`, реальный browser E2E на disposable базе, параллельные операции, sandbox платежей/касс/доставки, tenant RLS, backup/restore, 30-дневный SLO.

**План закрытия до релиза:** P0 — согласовать коммерческую готовность по нишам, оплату и фискализацию, реальное покрытие e2e и tenant security; P1 — унифицировать интерфейсы и миграцию из YCLIENTS/МойСклад, телефонию/лояльность и мобильные роли; P2 — автоматические рекомендации и расширяемые отраслевые сценарии.
