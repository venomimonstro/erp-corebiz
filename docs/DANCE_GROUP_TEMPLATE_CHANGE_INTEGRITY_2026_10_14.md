# CoreBiz — управление изменениями групповых занятий без потери обязательств

**Дата:** 14.10.2026  
**Пример:** студия танцев, Москва, два филиала, 52 тренера, более 12 направлений.  
**Статус:** реализован защитный API и интерфейс подтверждения; полный runtime E2E и PostgreSQL-тест не выполнялись.

## Зачем исправлено

Группа — это **шаблон будущей серии**, а `dance_lesson` и
`service_booking` — уже созданные конкретные записи с обязательствами
перед участниками. Ранее владелец мог изменить тренера, комнату,
вместимость или расписание `dance_group`, после чего будущие занятия
оставались с прежними параметрами. Пользователь не мог увидеть охват
**до** сохранения и мог ошибочно считать, что перенёс всю группу.

В YCLIENTS разделяются индивидуальная и групповая запись:
групповые занятия создаются как события, а права к журналу и
деталям визита управляются отдельно.
См. [групповые события](https://support.yclients.ru/599),
[права журнала](https://support.yclients.ru/284),
[права окна визита](https://support.yclients.ru/287).

## Что внедрено в main

1. `GET /api/v1/dance/groups/:groupId/impact` (право `dance.read`):
   возвращает версию группы, количество будущих занятий,
   количество неотменённых записей участников,
   начало/конец диапазона. Проверяет tenant и видимость группы.
2. `PATCH /api/v1/dance/groups/:groupId`:
   при материальных изменениях (тренер, зал/зона, филиал,
   вместимость, шаблон расписания или срок действия) и наличии
   будущих занятий требует
   `acknowledgeFutureLessonsUnchanged: true`.
   При отсутствии подтверждения возвращает 409,
   ничего не изменяя.
3. Остаётся `version` и проверка `version` на сервере.
   Предварительный просмотр не заменяет транзакционную
   сверку актуального состояния при сохранении.
4. В интерфейсе `/app/dance/groups` перед изменением шаблона
   отображается число затрагиваемых занятий и записей,
   обязательный checkbox и предупреждение о необходимости
   отдельно перенести существующие занятия и уведомить клиентов.
5. `dance-group-template-impact.spec.ts` проверяет:
   чтение без модификации, 409 без согласия,
   явное подтверждение без изменения `dance_lesson`,
   группу без будущих занятий и устаревшую версию.
6. `scripts/dance-owner-contract.test.mjs` включает
   проверку этих договорённостей на уровне исходников.

## Полный сценарий владельца

**Ситуация:** тренер увольняется, в группе 12 будущих занятий,
на 8 из них записаны клиенты.

- Владелец открывает группу и нажимает «Изменить».
- Система показывает количество будущих занятий и клиентов.
- Владелец выбирает другого тренера или время и подтверждает,
  что **существующие события пока не меняются**.
- Обновляется только шаблон будущих серий.
- Владелец переходит в календарь и вручную переносит
  конкретные занятия с сохранением истории и прав клиентов.
- При увольнении исходного тренера архивирование должно
  оставаться заблокированным, пока у него есть будущие
  активные занятия/записи.
- При конфликте версии показывается ошибка и предлагается
  обновить календарь.

## Универсальный принцип для всех ниш

Изменения **настроек** не равны изменениям **созданных операций**:

| Профиль | Шаблон | Фактический объект |
|---|---|---|
| Танцы | Группа и регулярное расписание | Урок, участники, абонемент |
| Салон | Услуга/смена мастера | Запись/визит с ценой и ресурсами |
| Автосервис | Шаблон работ, ставка механика | Заказ-наряд с согласованной сметой |
| Магазин | SKU/прайс | Принятая продажа/резерв/чек |
| Аренда | Тип ресурса и прайс | Договор/бронирование конкретного зала |
| Агентство | Шаблон работ/этапов | Согласованный проект/акт/счёт |

Далее применять аналогичный **предпросмотр последствий → явное
решение → проверка версии → транзакционное выполнение → аудит**
к критическим действиям на всех вертикалях. При этом нельзя
создавать дубли CRM, каталогов, денег или резервирования.

## Проверки и оставшиеся риски

Проверено наличие и связность изменений непосредственно
в файлах `main`. **Не подтверждены** компиляция TypeScript,
Jest и реальное поведение PostgreSQL на тестовой базе.
При выпуске обязательно:

```bash
git checkout main && git pull --ff-only origin main
pnpm test:dance:owner
pnpm typecheck && pnpm test && pnpm build
```

Важное ограничение: это пока **защита от неверного понимания
изменения шаблона**, но не функция массового безопасного переноса
уже оплаченных уроков. Для полноценной миграции расписания нужен
отдельный мастер с dry-run, проверкой занятости залов, сохранением
абонементов, уведомлением клиентов и атомарной записью изменений.
