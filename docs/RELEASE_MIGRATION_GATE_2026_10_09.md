# Ручной release gate: миграции и tenant isolation

Дата: 2026-10-09. Ветка: `main`. **CI/Actions не используются.**

## Обнаруженный блокер

Каталог `infrastructure/postgres` содержит повторяющиеся числовые префиксы миграций, в том числе `040`, `043`, `044`, `054`, `055`, `056`. Текущий migration runner сортирует имена файлов лексикографически и учитывает миграции по **полному имени файла**. Это не даёт математически однозначного порядка зависимостей по номеру и усложняет сопровождение разных установок. Само наличие дублей не доказывает, что какая-либо схема повреждена: реальную ситуацию необходимо проверить на чистой и обновляемой тестовых БД.

## Новый контроль

`node scripts/migration-preflight.mjs` выдаёт машиночитаемый отчёт о нумерации и опасных SQL-инструкциях. `scripts/release-check.sh` вызывает этот контроль **до** `typecheck`, тестов, сборки и тестового replay.

До урегулирования всех коллизий команда `pnpm release:check` закономерно завершается с BLOCK; её успех не следует имитировать флагами пропуска.

## Безопасный план устранения

1. Снять read-only выгрузку `schema_migration(filename, applied_at)` для каждого действующего окружения.
2. Сопоставить историю применения с Git SHA и содержимым миграций; зафиксировать отдельный перечень файлов, уже применённых где-либо.
3. На **новой одноразовой** БД воспроизвести нынешний порядок, сохраняя log и точку отказа.
4. Для ещё никогда не применявшихся файлов разрешено перенумерование новым именем. Для уже применявшихся файлов **нельзя просто переименовать**: нужно предусмотреть совместимую запись `schema_migration`, старое имя или отдельную forward-only reconciliation migration.
5. Зафиксировать инварианты RLS, FK/unique/check, tenant ownership и критические складские/финансовые балансы после replay.
6. Только после устранения конфликтов повторить `pnpm release:check` на явно подтверждённой одноразовой БД и выполнить cross-tenant, concurrency, restore-тесты.

## Проверка вручную

```bash
node scripts/migration-preflight.mjs

# Запуск только на одноразовой staging БД:
export COREBIZ_DISPOSABLE_DATABASE_URL='postgresql://...'
export COREBIZ_CONFIRM_DISPOSABLE_DB=YES
pnpm release:check
```

**Go/No-Go:** до подтверждённого replay и проверки работы через runtime DB role без SUPERUSER/BYPASSRLS production запуск запрещён. Наличие кода в main означает реализацию, но не доказанную production готовность.
