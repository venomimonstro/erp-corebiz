# CoreBiz — аудит интернет-магазина, переноса из 1С и запуска своего домена
Дата: 2026-10-11. Ветка: `main`. CI/GitHub Actions не используются.

## Итог

Фактическое состояние: **инженерный MVP, production NO-GO**. Наличие исходников не
равно подтверждённой готовности боевого магазина. Запуск реального магазина
после перехода с 1С требует проверки полного цикла данных, денег, складских
движений и регуляторных обязанностей на отдельном staging-окружении.

## Фактически найденные модули

| Контур владельца интернет-магазина | Текущее состояние |
| --- | --- |
| Справочники товара, варианты, SKU, штрихкоды, цены | Реализовано в Core, требуется нагрузочный и UX тест |
| Фотографии товаров | Первичное HTTPS-фото: добавлено в этой итерации; загрузки в собственное хранилище и галереи нет |

| Прямой обмен с 1С | Нет доказанного полноценного обмена CommerceML 2.x, UUID, остатками, ценами, заказами и изменениями |
| Миграция исторических заказов / оплат / складских остатков | Не реализована как управляемый cutover с reconciliation |
| Собственные склады, резерв, закупка, отгрузка | Модули реализованы, требуется E2E и сверка учётных регистров |

| Каталог публичной витрины | Теперь курсор, серверный поиск, фото, ограничение страницы до 100 SKU |
| Готовый сайт магазина | Создание шаблона STORE, каталога и конфигурации магазина одной транзакцией |
| Конструктор блоков, SEO, sitemap, OpenGraph | Базовые функции есть; нет богатого visual designer уровня Tilda |
| Подключение домена | DNS TXT-владение + статус активации + маршрутизация по Host существуют |
| Автоматический DNS/CNAME/A, HTTPS и сертификат | Не доказана автоматическая настройка, требуется внешняя проверка |
| Интернет-эквайринг, webhooks, подтверждение и возврат оплаты | **Нет подтверждённого готового публичного checkout с онлайн-оплатой** |
| Доставка, ПВЗ, расчёт тарифов, трек-номера | **Нет полноценной подключённой публичной доставки** |

## Что сделано в этом изменении

1. Режим `POST /api/v1/sites` c `template: "STORE"`: автоматически создаёт
   стартовую страницу (HERO + PRODUCT_GRID + преимущества) и
   `storefront_config` в **одной транзакции**, без частично включённого магазина.
2. `/app/migration`: новый мастер переноса товаров и клиентов из CSV/XLSX
   (файл до 10 МБ): автоматическое распознавание заголовков, предпросмотр,
   ошибки строк, подтверждение импорта и итоговая сверка. Административные
   права `migration.manage`; доступ из раздела «Онлайн-торговля» и конструктора
   сайтов. Не обещает поддержку CommerceML или импорт складских балансов.
3. `GET /api/v1/storefront/site/:siteId/readiness`: серверный tenant-scoped
   checklist по состоянию сайта, опубликованного каталога, цен, доступного
   запаса, домена и блокерам внешних интеграций.
3. В разделе «Сайты» — создание магазина отдельной кнопкой, панель
   готовности, предпросмотр и обновление проверки.
4. Публичная витрина: `GET /api/v1/storefront/:siteCode/catalog` с
   `limit` (1–100), `cursor` UUID, `q` (2–120 символов),
   выдачей `nextCursor`. Сначала выбирается страница SKU, затем считается ATP.
   UI: поиск и подгрузка следующих товаров.
5. Каталог и карточка магазина отображают `product.image_url`.
   API редактирования: `PATCH /api/v1/catalog/products/:productId/image`
   требует `catalog.write`, пишет audit event и не принимает не-HTTPS.
6. Добавлена `225_storefront_primary_product_image.sql` — схема фото товара.
7. Добавлена проверка совпадения валюты SKU и магазина при изменении корзины.
8. Checkout сообщает, что **онлайн-оплата не производится** и доставка
   отдельно согласуется. Прежняя Sales/OMS логика не подменяется фиктивным
   статусом PAID.
9. Импорт CSV/XLSX распознаёт больше распространённых полей выгрузки 1С,
   проверяет тип сущности и структуру входного запроса.
10. Тесты источника: `storefront-launch.spec.ts`.

## Приоритеты следующей реализации

### P0 — чтобы предприниматель реально мог перейти с 1С

- **Миграция без потери данных**: отдельно настроить 1C/CommerceML и CSV
  адаптеры; внешний GUID и таблицы mapping; категории, SKU, вариации, единицы,
  штрихкоды, фотографии, цены, остатки по складам, контрагенты, скидки, начальные
  взаиморасчёты, открытые заказы и резервы; dry-run, ошибки построчно,
  идемпотентность, rollback plan, сверка количества, стоимостей и документов.
- **Синхронизация на переходный период**: дельты заказов/цен/остатков,
  checkpoints, dead-letter и reconciliation, защита от повторов и гонок.
- **Checkout и приём оплаты**: эквайринг с webhook подписью, сверкой суммы,
  уникальными идентификаторами и состояниями; возвраты и частичные возвраты;
  только подтверждённый provider event может отмечать заказ оплаченным.
- **Доставка**: способы получения, тарифы, ПВЗ, адреса, статусы,
  отправления, стоимость доставки в снимке заказа, retries.
- **54-ФЗ и чековая модель**: интеграция кассы/ОФД, предоплата/зачёт/возврат
  в зависимости от схемы, надёжная обработка ошибок.
- **DNS и HTTPS**: явно документировать A/CNAME и required target;
  проверка фактической маршрутизации, выпуск/обновление TLS, canonical/redirect
  www ↔ apex, отделение произвольных Host от системного приложения.
- **Загрузка изображений**: собственный S3-compatible storage, контроль MIME,
  размеры, resize/webp, права tenant, квоты, CDN, thumbnails.
- **Acceptance gate**: migration replay, typecheck, тесты, build, HTTPS smoke,
  тест покупателя, PSP webhooks, доставка, возврат, бухгалтерская сверка и
  backup/restore на disposable окружении.

### P1 — чтобы превосходить Tilda / МойСклад в удобстве

- Действительно визуальный drag-and-drop редактор, библиотека готовых
  шаблонов, настройка темы без кода, preview mobile/desktop.
- SEO страницы категорий и товаров, ЧПУ, 301 redirect map при миграции,
  canonical/hreflang и product JSON-LD.
- Вариации, атрибуты, фильтры, поиск и сравнение, избранное, отзывы.
- Скидки/купоны, правила совместимости, комплекты и подарочные сертификаты.
- B2B личный кабинет, группы цен, счета, отложенная оплата, реквизиты.
- Расширенные документы поставщиков, ЭДО, интеграции маркировки.

## Бизнес-приёмка для пилотного интернет-магазина

1. Создать STORE через UI. Убедиться, что черновик не опубликован и
   storefront_config существует без повторного включения.
2. Импортировать каталог из Excel / выгрузки 1С и сверить по SKU / barcode /
   цене без дубликатов. Проверить tenant A не видит tenant B.
3. Принять товар на склад, установить safety stock, проверить ATP и карточку.
4. Опубликовать главную с PRODUCT_GRID, проверить SSR и видимость.
5. Подключить домен: TXT → VERIFIED → ACTIVE; отдельно проверить HTTPS и
   реальный маршрут на Caddy/Next, сертификат и robots/sitemap.
6. Выполнить два конкурентных checkout одного последнего SKU,
   сверить Sales/OMS/резерв/backorder и отсутствие двойного заказа.
7. Не показывать «оплачено», пока нет подтверждённого платежа и чека.
8. Проверить отмену, возврат, остаток, корректировки оплаты, покупателя.
9. Проверить права owner/manager/operator и read-only tenant.
10. Прогнать сборку и тесты **вручную** без GitHub Actions, затем
    backup/restore drill и согласовать pilot go/no-go.

## Локальная проверка без CI

```bash
corepack enable
pnpm install
pnpm typecheck
pnpm --filter @corebiz/api test -- --runInBand storefront-launch.spec.ts
pnpm test
pnpm build
```

Обязательные SQL-миграции запускать только после резервного копирования
и dry-run на отдельной базе. Сама запись коммитов в `main` не является
установкой на сервер и не доказывает production readiness.
