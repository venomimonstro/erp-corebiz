# Коммерческие спринты 22–28 — фактическое выполнение

Дата: 16.10.2026. Ветка: `main`. Без GitHub Actions / CI.
**Статус: частично реализовано; COMMERCIAL NO-GO.** Записи ниже отражают наличие кода, а не доказательство работающего production.

## 22. Оператор платформы — PARTIAL

- `platform_operator` отделён от OWNER/ADMIN клиентской компании.
- Read-only API `GET /api/v1/platform-operations/tenants?limit=25&offset=0` и страница `/platform-operations`.
- Доступ только при наличии ACTIVE `platform_operator`, активного пользователя и действующей **секретной** сессии (проверяется по SHA-256 cookie в SECURITY DEFINER-функции).
- В ответе только имя и состояние компании, план, период, число активных сотрудников и открытых обращений; без клиентских email, документов, паролей и токенов.
- Право оператора назначается вручную миграционным администратором БД. Для первой учётной записи после проверки личности пользователя DBA исполняет (не в API и не с обычной runtime-ролью):

```sql
INSERT INTO platform_operator(user_id)
SELECT id FROM app_user WHERE lower(email)=lower('operator@example.com')
ON CONFLICT (user_id) DO UPDATE SET status='ACTIVE',updated_at=now();
```

- **Не готово:** блокировки/разблокировки по процедуре, масштабный поиск, SLA и безопасный сервисный доступ к чужому tenant; операторская панель не умеет менять тарифы/проводки.

## 23. Подтверждение почты и восстановление доступа — PARTIAL

- `POST /api/v1/auth/password-reset/request` и `/complete`; `/forgot-password`, `/reset-password`.
- Token SHA-256, 30 минут, транзакционная выдача/погашение, новый пароль Argon2id, отзыв всех прежних сеансов.
- Одинаковый внешний ответ для известного и неизвестного адреса, лимит по IP/получателю, без сохранения открытой ссылки в БД или логах.
- Для доставки: `COREBIZ_UNISENDER_GO_KEY` и `COREBIZ_EMAIL_SENDER`, подтверждённый домен отправителя, HTTPS на `WEB_ORIGIN`. Endpoint Unisender Go зафиксирован в коде.
- В отсутствии рабочего провайдера запрос остаётся одинаковым для обоих типов адресов, а ошибка попадает в серверный лог. Это **не доказанная доставка**.
- Добавлен полный технический цикл **подтверждения адреса при регистрации**: `/auth/email-verification/status|request|complete`, `/verify-email`, `/app/verify-email`, попытка отправки после успешного создания аккаунта. Токен хранится только как SHA-256, истекает через 24 часа и погашается транзакционно; повторное письмо в течение 60 секунд не инвалидирует старую ссылку. Для запроса действует ограничение частоты.
- Пароль и подтверждение почты блокируют строки пользователя перед строками токена в одном порядке, чтобы не создавать взаимные блокировки. Предварительная проверка токена восстановления выполняется **до** Argon2.
- **Не готово:** смена подтверждённого адреса, повторная фоновая доставка, наблюдение за bounce, MFA, реальный provider sandbox E2E. При сбое почты регистрация сохраняется, а клиент может повторить запрос вручную.

## 24. Биллинг и платежи — EXISTING / BLOCKED

- Уже есть `CommercePaymentsService` и `/payments/saas/start` с ЮKassa, сохранением платёжного намерения, подтверждением и провайдерной сверкой.
- Добавлен `GET /api/v1/billing/events` для владельца с `billing.manage` и таблица истории подписки в настройках. Открытые payload и provider_reference не передаются пользователю.
- Существующее `billing.selectPlan` не позволяет бесплатно активировать платный тариф. Отсутствие subscription исправлено на READ_ONLY. **Новый платный checkout блокируется**, пока `app_user.email_verified_at` пустой; имевшиеся успешные транзакции по-прежнему подлежат сверке.
- Серверный коммерческий gate отказывает при отсутствии subscription или оплаченного ACTIVE без подтверждающих реквизитов. **Не считать это доказательством реального банковского перевода**.
- **Не готово:** многопериодная автоматическая рекуррентная оплата, полноценный документный/налоговый контур оператора, возврат SaaS, chargeback, платёжная банковская сверка, независимая песочница.

## 25. Выгрузка данных и вложения — PARTIAL

- Экспорт tenant уже был. Добавлен уникальный индекс на один `PENDING/PROCESSING` экспорт организации, конкурентная ошибка теперь `409` вместо дублирования. Миграция `255_tenant_export_claim_serialization.sql` исправляет выбор ранее упавших задач в старой очереди: worker блокирует tenant и не запускает параллельный экспорт из `FAILED` при наличии `PENDING/PROCESSING`.
- В регистрации вложения поддержки разрешён только ключ `tenants/<tenant_uuid>/support/...`, запрещены `..`, чужие namespace и произвольные пути.
- **Не готово:** подтверждение фактической принадлежности объекта в хранилище, сканирование, TTL ссылок, процедура удаления персональных данных, юрист/оператор ПДн.

## 26. Тарифные квоты — PARTIAL

- Миграция 252 заменяет совместный `FOR SHARE` на сериализующий `FOR UPDATE` по tenant subscription при создании/активации лицензируемых записей.
- При отсутствии subscription триггер больше не разрешает создание активной записи.
- **Не готово:** подтверждённый тест 100 одновременных попыток в PostgreSQL, лимиты хранения/почты/документов, экономика tenant на реальных расходах.

## 27. Поддержка — PARTIAL

- Закрыть тикет теперь можно только с итогом от 10 до 2000 символов. Результат добавляется в историю сообщений клиента, переход в CLOSED и действие аудита происходят в одной транзакции.
- Метаданные вложений имеют tenant-prefixed ключ; реальные загрузка и проверка содержимого ещё не подтверждены.
- **Не готово:** SLA, эскалация, публичная status-страница, алерты и сквозная поддержка внешних провайдеров.
