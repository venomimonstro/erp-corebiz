# CoreBiz — улучшение клиентского пути, 13.10.2026

## Изменено в этом спринте

### 1. Первый запуск /app/start
- Загрузка каталога ниш, сохранённого профиля и активации через независимые результаты `Promise.allSettled`. Отказ вспомогательного dashboard API не блокирует доступ к настройке ниши.
- Если текущий профиль недоступен, кнопка применения блокируется: нельзя незаметно заменить существующий профиль. Есть безопасная повторная загрузка.
- Отдельный блок **«Рекомендуемый следующий шаг»**, вычисляемый из первого незавершённого серверного milestone. Не хранит отдельные флаги на фронтенде.
- Новый раздел **«Можно ли работать с клиентами?»** читает `GET /go-live/readiness` и показывает реальные blocking checks с прямыми ссылками на исправление. Не смешивает milestone «первая польза» с коммерческим GO.
- Ошибка readiness не превращается в зелёную готовность, и не блокирует ручное заполнение бизнеса. Сервер остаётся источником истины.
- Сохранился подробный поэкранный маршрут всех 17 ниш.

### 2. Экран коммерческого запуска /app/settings/go-live
- После ошибки обновления старая готовность очищается. GO/LIVE недоступны, пока сервер заново не вернёт актуальный snapshot.
- Убраны системные `prompt()/confirm()`. Встроен доступный с клавиатуры блок подтверждения: основание решения (>=12 символов), галочка осознанного подтверждения, отмена, загрузка, явная ошибка и повторная сверка.
- Для GO продолжают действовать серверные блокеры, для LIVE необходимы HYPERCARE и проверки `GoLiveService`.
- Действие не делает deploy и не выдаёт ложных документов/чеков.

### 3. Меню и первая операция
- **Основные действия** (по умолчанию) и **Все инструменты**: меньше перегруженности для владельца небольшого бизнеса, при этом специализированные функции не удаляются.
- Выбор режима сохраняется отдельно по tenant и не меняет полномочий или доступ к API.
- Краткое меню для каждого типа бизнеса: услуги, танцы, авто, агентство, торговля, склад, универсальный профиль.
- Ссылка «Настроить бизнес» при наличии права customization.manage.
- Стартовые переходы для салона/барбершопа/маникюра теперь ведут в единое рабочее место `/app/service/desk`.

## Клиентская ручная приёмка — позитивный сценарий
1. Новый владелец регистрируется, выбирает профиль.
2. Открывает «Настроить бизнес» и видит следующий невыполненный шаг.
3. Заполняет услуги/товары, ресурсы и клиентскую базу.
4. Возвращается на старт и убеждается, что milestones изменились после серверного чтения.
5. Видит коммерческие blockers отдельно от первой операции.
6. Открывает «Основные действия» и переключается на «Все инструменты», без потери введённых данных.
7. Проверяет GO. Если блокеры не устранены, решение недоступно. После решения в форме появляется история.

## Негативные сценарии
- `/dashboard/activation` ответил 500: варианты ниш продолжают загружаться, прогресс отмечен как недоступный, можно повторить.
- `/customization/business-profile` ответил 500: применение неизвестного профиля запрещено.
- `/go-live/readiness` ответил 500: система не сообщает «готово»; повторная проверка обязательна.
- Клиент нажал GO, затем данные устарели: старый snapshot очищается.
- Клиент отказался подтверждать последствия: submit disabled; случайного перевода в HYPERCARE нет.
- Клиент имеет несколько компаний: режим меню хранится отдельно для каждого tenant; серверные RBAC/RLS остаются обязательными.

## Самопроверка
В `scripts/owner-industry-journeys.test.mjs` добавлены регрессионные условия для перечисленных UX-инвариантов. Выполнен независимый source-level контроль всех пяти групп: устойчивость загрузки, реальные blockers, отказ от stale GO, упрощённая навигация, переходы к единому рабочему месту. Все группы прошли статическую проверку; синтаксис новых Node-тестов проверен V8.

**Не выполнено здесь:** Next/TypeScript сборка, настоящие браузерные сценарии, Jest, PostgreSQL-интеграция, продакшен-сервер. Коммерческий GO не подтверждён. Для релиза обязательно `pnpm typecheck && pnpm test && pnpm build` и disposable `scripts/production-gate.sh`.
