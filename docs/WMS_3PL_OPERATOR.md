# WMS 3PL — рабочее место владельцев товара

## Назначение

Страница `/app/wms/owners` — управление справочником владельцев товарных остатков и контроль расхождений между общим Inventory/WMS и субрегистрами владельцев. Справочник одинаково применим к собственной торговой сети и 3PL-складу.

## Операции

- Выбрать склад и запросить reconciliation через `GET /wms/warehouses/:warehouseId/owner-reconciliation`.
- Посмотреть режим `TOTAL_ONLY` / `OWNER_LEDGER`, число несоответствий и строки с разницей.
- Создать 3PL owner, связав его с уже существующим `Party`. На MVP вводится UUID клиента; заменить выбором из CRM прежде чем запускать массовое внедрение.
- Активировать 3PL-контракт по выбранному складу. Денежные тарифы и сервисы договора здесь не редактируются.
- Включить owner ledger только после ручного подтверждения; серверная команда обязана выполнить сверку до переключения режима.

## Неприкосновенные инварианты

1. `inventory_balance` остаётся агрегированным источником движения физического остатка; `inventory_owner_balance` — owner projection/subledger.
2. Для `OWNER_LEDGER` сумма owner physical/reserved по складу и SKU должна совпадать с агрегатами.
3. Сумма `warehouse_location_owner_balance` по владельцам и адресу должна совпадать с location balance.
4. Изменение владельца товара не должно происходить через редактирование строки баланса: нужна отдельная доменная операция с обоими ledger movements.
5. Не должно быть silent repair: любое расхождение отображается и блокирует опасные операции до корректировки через легальный документ.
6. Для владельца `CLIENT` требуется активный `warehouse_3pl_contract` и режим `OWNER_LEDGER`.
7. RLS и разрешения `wms.read/wms.manage` проверяются в API, не только в интерфейсе.

## Ручная проверка до релиза

- [ ] Новая организация автоматически получает одного активного INTERNAL owner.
- [ ] Нельзя читать owner и ledger другой организации.
- [ ] Повторная инициализация не создаёт повторных bootstrap movements.
- [ ] Отсутствующий 3PL-контракт отклоняет движения CLIENT owner.
- [ ] Расхождение адресного и агрегированного учёта останавливает включение OWNER_LEDGER.
- [ ] Получение, размещение, резерв, отбор и отгрузка сохраняют ownerId.
- [ ] После каждого движения инварианты aggregate↔owner↔location сходятся.
- [ ] Два конкурентных резерва одного owner/SKU не превышают доступный остаток.
- [ ] `pnpm typecheck`, `pnpm build` и полный прогон миграций на пустой PostgreSQL.
- [ ] На сервере выполнен backup/restore drill.

**Статус:** UI + существующие API подключены в main. Production gate НЕ подтверждён, до локальной проверки не утверждать готовность 3PL.
